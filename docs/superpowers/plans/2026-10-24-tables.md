# Tables ("tafels") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Typed, timed decks ("Typen op tijd") with a per-child time limit and a generator for multiplication and division tables 1–10.

**Architecture:** Two new columns (deck answer mode, child time limit) in migration 002. Sums are ordinary cards: the tables generator only produces pasted lines (`1 × 4 = 4`) that go through the existing paste preview and card creation. The session payload tells the browser, per card, the time limit (or none); the browser times and judges the answer and posts known/not known exactly as today.

**Tech Stack:** Rust (axum, rusqlite), Svelte 5 + TypeScript, `node --test`, the CDP e2e script.

**Spec:** `docs/superpowers/specs/2026-10-24-tables-design.md` (extends `docs/superpowers/specs/2026-10-08-family-flashcards-design.md`).

## Global Constraints

- Answer mode values: `self` ("Zelf beoordelen", default) and `timed` ("Typen op tijd").
- A `timed` deck always has direction mode `front_to_back`.
- Child time limit: stored in milliseconds, default 3000, allowed 1000–30000 in steps of 500.
- Tables 1 to 10; table n gives `k × n = k·n` and `k·n : n = k` for k = 1..10; "×" (U+00D7) and ":" with one space either side.
- Child copy, exact: "✓ Goed!", "Goed, maar nog wat sneller! (4,2 s)", "Het is 24", "Goed! (5,1 s)", "Verder", "Controleer". Seconds with one decimal and a decimal comma.
- No visible countdown while the child thinks; no arrow/space shortcuts on timed turns.
- Specs stay tech-agnostic: spec edits describe behaviour, not code.
- Commit after each task; push only when the user asks.

## Review Focus

- A parent switches an existing "both" deck to "Typen op tijd": the server must refuse anything but `front_to_back`, the form must send it. (Task 1 test.)
- Time limit 0, 31 s or 3,2 s posted by hand: rejected with `{"error":"invalid","field":"time_limit_ms"}`. (Task 1 test.)
- Old databases: existing decks become `self`, existing children get 3000 ms, nothing else changes. (Task 1 test.)
- A right but slow answer on a practice repeat must end the repeat loop. (Task 3 test.)
- Fast answers on a timed deck must not raise the "clicking through" warning, even when mixed with self-judged answers. (Task 2 test.)
